# 均匀分赃

[打开网页](https://zxzin.github.io/jun-yun-fen-zang/)

金钱、百分比、自定义资源，2–12 人共同分配。

## 两种方式

- **分享邀请**：填写主题、总量和参与者，每人一条专属邀请。领取后在自己的浏览器分配、封存，全部提交后显示最终建议。
- **本地分**：同一台手机轮流填写，封存后保存到当前浏览器，刷新可继续。

所有人的金币栏同时展示，向上推增加、向下推减少，金额与叠层同步变化。其余份额按原比例调整，总量保持不变。加减按钮每次调整约 1%，点击金额可精确修改。百分比总量固定为 100%。5 人及以上使用紧凑金币栏。

每个人提交完整分配，并选择自己接受的浮动范围。底部主按钮进入封存；歪歪抱住盒子，卡片沿着指引进入盒口，合盖后直接交给下一位。点击“封存我的方案”和键盘同样可用。云端模式等待保存成功才显示封存成功。结果由每位参与者确认自己的份额；范围冲突时可再分一轮。

按钮、人数键、选项和金币微调共用玻璃控件：轻透高光、按压回弹、单一滑动选中层。人数变化原位更新数字与玩家标记，保留当前滚动位置。系统开启减少动态效果或减少透明度时，保留同样的操作与清晰反馈。

## 算法

每份完整方案权重相同。先按人求平均，再在每人的接受范围内，找与平均方案平方偏差之和最小的分配，同时保持总量一致。

总量 10,000，三份方案为 `[5000,3000,2000]`、`[4000,4000,2000]`、`[4000,3000,3000]`，平均约为 `[4333.33,3333.33,2333.33]`。三人都接受自身期望 ±20% 时，第三人至少接受 2400，最终为 `[4300,3300,2400]`。

最小单位为整份或 0.01，整数尾差按最小增量偏差补齐，同等条件按席位编号。若所有最低值之和超过总量，或最高值之和不足总量，会标记冲突并给出平均参考。原接受范围保持不变。

这是一份协商建议。高报、范围选择与串通会影响结果；系统无法验证真实贡献，也无法保证所有人满意。

## 邀请与隐私

GitHub Pages 托管网页；Vercel Functions 和私有 Blob 保存云端房间。无需注册账号。每条邀请绑定一个房间和席位，首次领取后交换为该浏览器独有的随机凭证。后续读写由服务端检查凭证，发起人只看进度，成员只能提交自己的方案、确认自己的结果。原始方案和个人接受上下限不向其他人返回。

邀请令牌放在 URL 的 fragment 中，网页设为 `no-referrer`，无埋点和第三方前端脚本。领取前拥有链接的人均可领取，因此应单独发给对应参与者。首次领取后的链接不再能被另一浏览器领取。清理浏览器数据或换设备会失去访问凭证；当前不提供账号找回。

房间有效期 7 天，到期服务端拒绝访问。到期限制与物理删除是不同操作，当前没有自动清理存储任务。运营者和云服务提供方有后台数据访问能力，未实现端到端加密。最终结果可以下载为文本。

本地模式不上传输入。当前浏览器 localStorage 保存已封存的方案，开发者工具仍可读取，适合同桌信任场景。未封存的草稿不会保存。下载 `local.html` 后可离线打开，默认选择本地分；文件方式的保存支持取决于浏览器。

## 开发与部署

- `python3 build.py`：生成 `index.html`、默认本地模式的 `local.html` 和版本入口 `play-5.5.1.html`，图片、样式和前端代码内嵌。
- `npm ci --ignore-scripts && npm test`：算法、10,000 组多人范围场景、边界、服务端权限、并发领取/提交测试。
- `node qa/general-browser.test.cjs`：本地手机/桌面、触摸、键盘、隐私和恢复测试。
- `node qa/cloud-browser.test.cjs`：三浏览器上下文连接真实服务逻辑的本地联测；设置 `LIVE_URL` 可验证正式环境。
- 浏览器测试可用 `PLAYWRIGHT_MODULE` 和 `CHROME_PATH` 指定现有 Playwright/Chrome。
- `api/rooms.js`：仅允许网页源 `https://zxzin.github.io`，服务端私有存储以 ETag 条件写保护并发更新。
- Vercel 项目 `junyun-rooms`，连接 Production 的私有 Blob，以 `BLOB_STORE_ID` 和 Vercel OIDC 授权。无客户端存储密钥；存储未连接时返回 503。
- main 推送触发 GitHub Pages 构建/测试/发布与 Vercel 后端构建。公开页面目录仅含 HTML 与图标，不包含服务端配置或房间数据。
- 当前限制每小时最多创建 30 个房间。存储套餐额度用尽或服务中断时页面保留草稿并提示重试。

## 角色与场景

5.5.1 沿用「圆团大眼·细腻彩铅」YY 母版。睁眼与蒙眼两张透明原图位于 `assets/yy-round-v6.png`、`assets/yy-blind-v6.png`，内嵌页面使用对应 WebP。生成使用内置 ImageGen，完整提示词见 `assets/yy-v6-prompts.json`。

金币以圆耳、大眼睛和金色浮雕组成鼠鼠币面，每堆顶部显示完整头像，下方露出金色币边。三堆前后错落表现相对份额，具体数量以每栏顶部数字为准。原图 `assets/yy-mouse-coin-v12.png` 由内置 ImageGen 使用原鼠鼠金币与 YY 大眼母版作为实际输入编辑，提示词见 `assets/yy-mouse-coin-v12-prompts.json`；页面内嵌压缩 WebP。触摸推拉时金币逐层增减，操纵钮与整栏高亮；首页、交接、分配、封存、邀请和结果页使用同一套浅蓝场景、白色操作卡、彩色玩家标记和蓝色主按钮。封存采用抱盒子的 YY，手与道具保持接触；两张开合状态原图位于 `assets/yy-box-open-v8.png`、`assets/yy-box-closed-v8.png`，提示词见 `assets/yy-v8-prompts.json`。

## 分配验证

固定种子构造 3–12 人各 1,000 组，共 10,000 组：6,648 组有可行解，全部落在个人填写范围并保持总量；3,352 组范围冲突，全部识别。构造样本用于验证算法，比例代表测试覆盖，不代表真实用户满意率。测试运行后生成 `qa/v7-allocation-results.md` 与 JSON 明细。

当前 5.5.1 位于开发分支。正式共享房间仍等待 Production 私有存储连接与真实联测，GitHub Pages 主站尚未发布本版。
