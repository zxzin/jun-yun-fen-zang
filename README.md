# 均匀分赃

[手机打开，来分一局](https://zxzin.github.io/jun-yun-fen-zang/)

歪歪蒙眼守盒，每个人打一次小算盘。2–12 人在同一台设备轮流盲填，最后一起看综合分配建议。

## 怎么玩

1. 选金钱、百分比或自定义资源，设置总量与人数。百分比固定合计 100%。
2. 约定好各自几号玩家。轮到自己时，同屏比较所有人的份额。
3. 拉动任意滑杆，其他人的份额按原比例联动；其余全为零时均分剩余量。总量始终一致，也可精确输入数值。
4. 选择围绕自己这一份的接受范围，把完整分配卡拖进盒口，看到吸入、合盖、上锁、盖章。支持点击和键盘封存。
5. 全员完成后一起开盒，查看结果、现场认可并导出文字文件。

## 算法

每位玩家提交一份总量完整的方案，每份权重相同。系统平均各列，随后在各人自报接受范围内，最小化与平均方案的平方偏差之和。

例如总量 10,000，A/B/C 分别提交 `[5000,3000,2000]`、`[4000,4000,2000]`、`[4000,3000,3000]`。平均得到约 `[4333.33,3333.33,2333.33]`。各人接受自己的期望 ±20% 时，C 最低接受 2400，最终调整为 `[4300,3300,2400]`。

金额和百分比以 0.01 为最小单位，自定义支持整份或 0.01。先求受范围限制的连续投影，再按最小边际偏差补齐整数尾差，同等条件按玩家编号。所有最低值之和超过总量、或所有最高值之和低于总量时，保留原范围并明确标记冲突，展示不受范围限制的平均参考。

这是协商建议。高报、范围选择与串通可能影响结果；系统无法验证真实贡献，也不保证策略诚实、博弈均衡或全员满意。

## 保存、分享与隐私

当前支持同设备轮流填写。网站链接可以分享，朋友在另一台设备打开会开始独立的一局；异地共同房间和答案回传尚未接入。

每次封存后将本局写入当前浏览器的本地存储，刷新或重新打开后点“继续上次”。尚未封存的草稿不保留；重开和清理浏览器数据会移除本局。浏览器拒绝存储时会提示保持页面打开。最终结果可下载保存。

网页没有账号、后台、第三方脚本、埋点或用户输入上传。GitHub Pages 首次提供页面，托管访问日志由 GitHub 管理。输入数据留在本机，开发者工具能够读取，适合彼此信任的参与者。交接与后台遮屏移除私密编辑界面，原始完整方案不会在最终结果页展开。

下载 index.html 后可离线运行，全部图片和代码已内嵌。文件方式的持久存储能力由浏览器决定，建议用同一个浏览器打开线上网址以保留进度。

## 开发

- 源码：src/；平面歪歪原图及无损 WebP：assets/。
- 构建：`python3 build.py`，Python 标准库即可。
- 算法测试：`node --test qa/engine.test.cjs`。
- 浏览器测试：安装 Playwright 和 Chrome，通过 PLAYWRIGHT_MODULE、CHROME_PATH 指定安装路径，再执行 `node qa/general-browser.test.cjs`。
- main 分支推送后 GitHub Actions 重建页面、验证提交产物与算法，再发布 GitHub Pages。
